# Data preparation protocol

The current baseline accepts UTF-8 text files with one complete document per non-empty line. JSONL datasets must first be exported by selecting the text field into this format; the exporter should record its source dataset, revision, configuration, license, selection rule and export code version.

For a corpus with a sealed test set, run `frontier prepare-data --input SOURCE.txt --output data/corpus --validation-fraction 0.05 --test-fraction 0.05 --seed 17 --content-origin human` after verifying the source text is human-authored. Supply a JSON source sidecar with `--source-metadata` when available. Schema 4 writes `train.txt`, `validation.txt`, `test.txt` and a versioned `data_manifest.json`. It assigns normalized duplicates together, retains and reports duplicate rows, and records SHA-256 identities for each normalized document without placing document text in the manifest. `load_split` reads only training and validation documents; `load_all_splits` is the explicit access path for a final test evaluation. A zero `--test-fraction` keeps the legacy train/validation schema for existing workflows. Preparation refuses to overwrite a non-empty output directory; use a new directory for every corpus revision.

`content_origin` is one of `human`, `synthetic`, `mixed`, or `unknown`. The CLI defaults to source metadata when available and otherwise records `unknown`; older manifests also load as unknown. Do not infer origin from a dataset name, license, or the `synthetic_fixture` field. That legacy field identifies the built-in smoke fixture. TinyStories source metadata records `synthetic` explicitly. New source metadata should include dataset, revision, license and origin. The manifest hashes that metadata and its preprocessing contract; each run summary also hashes the exact manifest and reports UTF-8 byte counts and tokenizer token counts. The comparison tool permits narrow metric comparison with incomplete legacy records but blocks a research claim unless the tokenizer artifact, dataset source metadata, manifest and preprocessing identity are pinned.

The experiment configs refer to `data/tinystories` as a location only. No dataset is bundled or assumed licensed by this repository. Confirm the source license and usage terms, and use the same exported files for every control and candidate. Keep the data outside Git; record the manifest with each run. Tokenizers are saved as versioned JSON artifacts whose SHA-256 is recorded in both run and evaluation metadata. The byte tokenizer's artifact spells out the UTF-8 byte mapping and special-token contract; learned tokenizers must serialize their full vocabulary and merge/model data before they are eligible for comparison.

## Candidate corpus review

WikiText-103 raw was a plausible diagnostic candidate because its publisher describes full Wikipedia articles and the original language-modeling benchmark, but it was not selected. The [Salesforce dataset card](https://huggingface.co/datasets/Salesforce/wikitext) shows `cc-by-sa-3.0` and `gfdl` metadata tags while its licensing paragraph says CC BY-SA 4.0; the [publisher's loader at a pinned revision](https://huggingface.co/datasets/Salesforce/wikitext/blob/8aaa8b27d493dba10b8553290236799e6dc57829/wikitext.py) also declares CC BY-SA 4.0. The [Wikimedia Terms of Use](https://foundation.wikimedia.org/wiki/Terms_of_Use?useformat=mobile) describe page-level licensing and attribution, including imported text that may not be GFDL. The WikiText release does not provide the article revision and attribution mapping needed here to resolve which terms apply to every selected document. Both WikiText sizes are small, but the license and document-identity gaps remain. No WikiText files have been downloaded for this project.

### Q10.a correction — source-use restriction and replacement (23 September 2026)

The OpenStax choice above is withdrawn before acquisition. The current [book-specific publisher page](https://openstax.org/books/principles-economics-2e/pages/preface) states that the book may not be used to train large language models or otherwise ingested into generative-AI offerings without OpenStax's permission. The page also states CC BY 4.0, but that does not resolve the separate training restriction for this project. No OpenStax PDF or text was downloaded or used.

The replacement source is a bounded custom snapshot of English Wikipedia article revisions fetched by exact revision ID through the [official MediaWiki API](https://www.mediawiki.org/wiki/API%3ARevisions). This is not the WikiText release: each selected article must have a pinned revision permalink and item-level attribution. Wikimedia's [Terms of Use](https://foundation.wikimedia.org/wiki/Terms_of_Use?useformat=mobile) allow text reuse with attribution by linking to the source article, whose history identifies its contributors; the [developer guidance](https://foundation.wikimedia.org/wiki/Legal%3AWikimedia_Developer_App_Guidelines) says most Wikimedia text is CC BY-SA 4.0 and directs reusers to inspect the page footer, history, and discussion for item-specific terms. The official [CC BY-SA 4.0 legal code](https://creativecommons.org/licenses/by-sa/4.0/legalcode) requires attribution and ShareAlike for distributed adaptations. Q10.b must exclude non-text media, fair-use material, and pages with third-party or license notices that cannot be preserved, and store each exact oldid permalink with the prepared manifest. For API use, follow [API etiquette](https://www.mediawiki.org/wiki/API%3AEtiquette): identify the client, issue serial requests, and use `maxlag` for noninteractive runs. This correction supersedes the chapter-based split wording in the paragraph above: the split unit is a complete article revision.

This is a bounded English-encyclopedia diagnostic, not a broad capability benchmark. The source terms reviewed do not expressly discuss language-model training; treating reuse under the page's CC BY-SA terms as sufficient for this local research use is an interpretation, not an explicit AI-training grant. No source text or trained model will be published under this Q10 package. Any later distribution of derived artifacts needs a separate license review. Q10.b must use a descriptive API User-Agent, serial requests and `maxlag`, freeze the exact article/revision inventory before corpus acquisition, and stop if per-page licensing or attribution cannot be verified. The source API metadata endpoint was unavailable from the restricted checkout during the initial Q10.b preparation package; metadata access was later obtained through serial, metadata-only requests. No replacement corpus has been downloaded.

### Q10.b candidate inventory preregistration (23 September 2026)

Before querying revision metadata, freeze the candidate titles and eligibility rules in [`q10b_wikipedia_candidate_inventory.json`](q10b_wikipedia_candidate_inventory.json). The list contains 24 titles across six topical strata. Use every eligible title; do not select pages based on their content or model scores. At least 20 pages must pass. Each selected revision must be wikitext, at most 1 MiB, and the combined source revision size must not exceed 4 MiB. If the bound or minimum is not met, stop and amend the candidate-set decision before requesting any article bodies.

The metadata-only query requests title/page identity, latest revision ID, timestamp, byte size, SHA-1, content model, and edit comment. It does not request `rvprop=content`. The English Wikipedia [Revisions API](https://www.mediawiki.org/wiki/API%3ARevisions) documents these metadata fields separately from revision content. Use one request for all candidates where supported, otherwise serial batches, with `maxlag=5` and a descriptive User-Agent under [API etiquette](https://www.mediawiki.org/wiki/API%3AEtiquette). After revision IDs are frozen, inspect each exact revision's footer, history and discussion for the license and attribution conditions described in the [Wikimedia Terms of Use](https://foundation.wikimedia.org/wiki/Terms_of_Use?useformat=mobile) and [developer guidance](https://foundation.wikimedia.org/wiki/Legal%3AWikimedia_Developer_App_Guidelines). Do not fetch corpus text unless at least 20 pages pass every metadata, size, license and attribution rule. Record excluded pages and reasons; no silent substitutions.

The 24-title metadata query completed on 23 September 2026. All 24 revisions are namespace 0, non-redirect, main-slot wikitext; the largest is 331,340 bytes and the combined inventory is 3,272,433 bytes. The audit covered no more than the newest 500 history entries at or before each pinned revision, not full page histories; therefore no candidate is cleared yet. See the inventory's `audit.page_findings` for the recorded holds. No raw revision-content API field was requested and no corpus text was saved or prepared. The auditors did load rendered oldid pages to read the requested footers; those responses included page HTML but the article text was not retained or used for corpus selection. Q10's body-acquisition gate remains closed until at least 20 pages have complete, traceable rights and attribution evidence.

For early infrastructure checks, `configs/smoke.json` creates a fixed synthetic fixture automatically. Its scores are not downstream language-capability evidence.

## Reproducing the bounded TinyStories subset

The M1 corpus run uses bytes 0–20,971,519 of `TinyStories-train.txt` at the pinned `roneneldan/TinyStories` revision `f54c09fd23315a6f9c86f9dc80f725de7d8f9c64`. The [dataset card](https://huggingface.co/datasets/roneneldan/TinyStories/blob/f54c09fd23315a6f9c86f9dc80f725de7d8f9c64/README.md) declares `cdla-sharing-1.0` and describes the dataset as synthetic short stories. The experiment deterministically holds out 2% of selected documents from this training prefix; it does not use the dataset's separate validation file. This bounded split verifies training and evaluation plumbing, not broad capability.

`scripts/prepare_tinystories_prefix.py` splits on `<|endoftext|>`, discards the last partial story if the byte range cuts through one, and collapses story whitespace to single spaces. It writes one document per line and a provenance sidecar containing the dataset revision, source file, license, byte range, upstream size, raw-prefix SHA-256, complete-story count, discarded-tail size, and text transformation. It refuses to overwrite the downloaded prefix or either existing prepared output. Pass the sidecar to `frontier prepare-data --source-metadata`; the resulting split manifest is copied into every run. Raw and prepared corpus files remain local under the root `data/` directory, which is git-ignored.

### Q10.a amendment 2 — PMC Open Access metadata-only candidate screen (23 September 2026)

The Q10-SOURCE-001 Wikipedia screen remains in the experiment history: its 24 exact revisions met namespace/content-model/size rules, but zero pages had complete history and attribution evidence, so no body was requested. The completed Q10-SOURCE-002 screen used the [PMC Open Access Subset](https://pmc.ncbi.nlm.nih.gov/tools/openftlist/) and its official [article-dataset documentation](https://pmc-oa-opendata.s3.amazonaws.com/README.txt). PMC says article licenses vary by version and requires the item-level license to be followed; per-version JSON includes a license code, manuscript/OCR/retraction flags, XML URL and MD5. The source documentation also describes a daily S3 inventory, version behavior, approved retrieval services, required NLM acknowledgement, and possible third-party rights in media. See the [PMC Cloud documentation](https://pmc.ncbi.nlm.nih.gov/tools/pmcaws/), [search syntax](https://pmc.ncbi.nlm.nih.gov/about/userguide/), [OAI-PMH metadata service](https://pmc.ncbi.nlm.nih.gov/tools/oai/), and [copyright notice](https://pmc.ncbi.nlm.nih.gov/about/copyright/).

The executed six-stratum metadata screen followed the frozen selection in [`q10c_pmc_candidate_inventory.json`](q10c_pmc_candidate_inventory.json). First freeze 24 unique PMCID candidates by numeric query order, without inspecting or replacing metadata-ineligible candidates. Then inspect only PMC Cloud per-version JSON, S3 object-list metadata, and OAI-PMH compact Dublin Core (`metadataPrefix=oai_dc`); do not request full-text or `pmc_fm` records. Process only the OAI identifiers, title, creator, date, subject/citation and rights fields; discard any `dc:description` that contains abstract text. Because `license_code` identifies a Creative Commons family rather than its exact version, require that it maps to CC BY and that OAI `dc:rights` is exactly the [CC BY 4.0 legal URI](https://creativecommons.org/licenses/by/4.0/legalcode). Also require exactly one Cloud version per PMCID, non-manuscript/non-historical-OCR/non-retracted flags, a present XML object, and complete citation metadata. Retain the raw rights fields, canonical license URI, author/title/journal, publication year, DOI, exact PMCID version, source article URL, XML MD5, S3 modification date, and object size. Candidate XML is capped at 1 MiB per article and 4 MiB combined across all metadata-eligible candidates; at least 20 of the frozen 24 candidates must pass before any article XML may be requested through an approved PMC service. The six [MeSH topic queries](https://pmc.ncbi.nlm.nih.gov/about/userguide/) restrict this source screen to the MEDLINE-indexed subset; it does not support a general-English capability claim.

If a future source passes its metadata gate, inspect each exact XML license statement and any separately licensed notices. Exclude figures, captions and supplements unless their individual rights are verified, and exclude any text whose license or attribution cannot be traced. Require at least 20 documents to remain before preparation. Then use the existing schema-4 document-level split and normalized-duplicate grouping, fit the tokenizer on training documents only, and freeze the validation/test identities. At amendment 2 preregistration no PMCID candidates were selected; at amendment 3 closeout, 5 of 24 passed metadata review, the minimum-20 gate failed, and no article body or media was requested.

### Q10.a amendment 4 — PMC publication-stage filtered candidate screen (23 September 2026)

Q10-SOURCE-002 is closed with 5 of 24 metadata-eligible versions (547,447 XML bytes); its at-least-20 gate failed. Twelve of the 24 records were flagged as author manuscripts, and five had multiple available Cloud versions. The official [PMC User Guide](https://pmc.ncbi.nlm.nih.gov/about/userguide/) documents the `"author manuscript"[filter]` and `preprint[filter]` query filters. The new screen applies both exclusions before candidate selection and creates a separate cohort; none of the earlier 24 IDs may be substituted into it.

The preregistered Q10-SOURCE-003 candidate rule specified six strata, eight unique IDs per stratum (48 total), ascending numeric PMCID order and the original stratum priority. Each query is capped at 1,000 IDs; do not replace ineligible candidates. Hash each returned ID list as UTF-8 of its exact numeric ID strings in original API order joined by commas, with no trailing comma. The selected-candidate digest uses UTF-8 `stratum_name<TAB>PMCID` rows in selection order, separated by LF without a trailing LF. The exact query, fields, eligibility rules, hashes and body gate are in [`q10d_pmc_published_candidate_inventory.json`](q10d_pmc_published_candidate_inventory.json). The intended screen retained the 2018–2025 date filter, CC BY search filter, exact canonical CC BY 4.0 OAI-rights rule, one-version requirement, 1 MiB per-article XML limit, 4 MiB aggregate limit and minimum 20 eligible versions. This cohort targets published biomedical/life-sciences articles and does not support a general-English capability claim.

This amendment was preregistered before the six E-Utilities ID queries, which were run once on 23 September 2026. All six ESearch translations turned the attempted `AND NOT` filters into positive AND terms; each warning list included `NOT` and `No items found.` All returned counts and ID lists were zero, so the 48-candidate selection gate failed before per-version metadata screening. The query strings, translations, warnings and empty-list hashes remain in [`q10d_pmc_published_candidate_inventory.json`](q10d_pmc_published_candidate_inventory.json). ### Q10.a amendment 5 — PMC Boolean grouping correction (23 September 2026)

The Q10-SOURCE-003 attempt failed before candidate selection because ESearch treated both excluded filters as positive AND terms when written as `AND NOT ... AND NOT ...`. The [PMC User Guide](https://pmc.ncbi.nlm.nih.gov/about/userguide/) documents uppercase Boolean operators and parenthesized grouping. The [NIH Preprint Pilot FAQ](https://pmc.ncbi.nlm.nih.gov/about/nihpreprints-faq/) shows a positive query followed by `NOT preprint[filter]` and states that E-utilities syntax requires a search term before Boolean `NOT`.

Q10-SOURCE-004 is a new, separately preregistered query attempt. It keeps the six topic strata, 48-candidate target, date/license filters, candidate order, per-version checks and size thresholds unchanged. Its query shape groups all positive terms first, then appends one exclusion clause: `(<positive terms>) NOT ("author manuscript"[filter] OR preprint[filter])`. The protocol adds a fail-closed ESearch translation check before proceeding to another stratum or selecting IDs. The exact expression, check, fields, hash encodings and body gate are in [`q10e_pmc_corrected_candidate_inventory.json`](q10e_pmc_corrected_candidate_inventory.json). None of the zero-ID Q10-SOURCE-003 results are reused.

At this amendment's preregistration, Q10-SOURCE-004's six queries have not been run. No new candidate IDs or per-version metadata have been requested, and no article XML, body, figures, supplements or prepared corpus text have been acquired. Article content remains gated on all 48 candidates being screened, at least 20 passing, and total eligible XML no more than 4 MiB.
