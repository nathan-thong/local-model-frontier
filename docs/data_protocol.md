# Data preparation protocol

The current baseline accepts UTF-8 text files with one complete document per non-empty line. JSONL datasets must first be exported by selecting the text field into this format; the exporter should record its source dataset, revision, configuration, license, selection rule and export code version.

For a corpus with a sealed test set, run `frontier prepare-data --input SOURCE.txt --output data/corpus --validation-fraction 0.05 --test-fraction 0.05 --seed 17 --content-origin human` after verifying the source text is human-authored. Supply a JSON source sidecar with `--source-metadata` when available. Schema 4 writes `train.txt`, `validation.txt`, `test.txt` and a versioned `data_manifest.json`. It assigns normalized duplicates together, retains and reports duplicate rows, and records SHA-256 identities for each normalized document without placing document text in the manifest. `load_split` reads only training and validation documents; `load_all_splits` is the explicit access path for a final test evaluation. A zero `--test-fraction` keeps the legacy train/validation schema for existing workflows. Preparation refuses to overwrite a non-empty output directory; use a new directory for every corpus revision.

`content_origin` is one of `human`, `synthetic`, `mixed`, or `unknown`. The CLI defaults to source metadata when available and otherwise records `unknown`; older manifests also load as unknown. Do not infer origin from a dataset name, license, or the `synthetic_fixture` field. That legacy field identifies the built-in smoke fixture. TinyStories source metadata records `synthetic` explicitly. New source metadata should include dataset, revision, license and origin. The manifest hashes that metadata and its preprocessing contract; each run summary also hashes the exact manifest and reports UTF-8 byte counts and tokenizer token counts. The comparison tool permits narrow metric comparison with incomplete legacy records but blocks a research claim unless the tokenizer artifact, dataset source metadata, manifest and preprocessing identity are pinned.

The experiment configs refer to `data/tinystories` as a location only. No dataset is bundled or assumed licensed by this repository. Confirm the source license and usage terms, and use the same exported files for every control and candidate. Keep the data outside Git; record the manifest with each run. Tokenizers are saved as versioned JSON artifacts whose SHA-256 is recorded in both run and evaluation metadata. The byte tokenizer's artifact spells out the UTF-8 byte mapping and special-token contract; learned tokenizers must serialize their full vocabulary and merge/model data before they are eligible for comparison.

## Candidate corpus review

WikiText-103 raw was a plausible diagnostic candidate because its publisher describes full Wikipedia articles and the original language-modeling benchmark, but it was not selected. The [Salesforce dataset card](https://huggingface.co/datasets/Salesforce/wikitext) shows `cc-by-sa-3.0` and `gfdl` metadata tags while its licensing paragraph says CC BY-SA 4.0; the [publisher's loader at a pinned revision](https://huggingface.co/datasets/Salesforce/wikitext/blob/8aaa8b27d493dba10b8553290236799e6dc57829/wikitext.py) also declares CC BY-SA 4.0. The [Wikimedia Terms of Use](https://foundation.wikimedia.org/wiki/Terms_of_Use?useformat=mobile) describe page-level licensing and attribution, including imported text that may not be GFDL. The WikiText release does not provide the article revision and attribution mapping needed here to resolve which terms apply to every selected document. Both WikiText sizes are small, but the license and document-identity gaps remain. No WikiText files have been downloaded for this project.

### Q10.a correction — source-use restriction and replacement (23 September 2026)

The OpenStax choice above is withdrawn before acquisition. The current [book-specific publisher page](https://openstax.org/books/principles-economics-2e/pages/preface) states that the book may not be used to train large language models or otherwise ingested into generative-AI offerings without OpenStax's permission. The page also states CC BY 4.0, but that does not resolve the separate training restriction for this project. No OpenStax PDF or text was downloaded or used.

The replacement source is a bounded custom snapshot of English Wikipedia article revisions fetched by exact revision ID through the [official MediaWiki API](https://www.mediawiki.org/wiki/API%3ARevisions). This is not the WikiText release: each selected article must have a pinned revision permalink and item-level attribution. Wikimedia's [Terms of Use](https://foundation.wikimedia.org/wiki/Terms_of_Use?useformat=mobile) allow text reuse with attribution by linking to the source article, whose history identifies its contributors; the [developer guidance](https://foundation.wikimedia.org/wiki/Legal%3AWikimedia_Developer_App_Guidelines) says most Wikimedia text is CC BY-SA 4.0 and directs reusers to inspect the page footer, history, and discussion for item-specific terms. The official [CC BY-SA 4.0 legal code](https://creativecommons.org/licenses/by-sa/4.0/legalcode) requires attribution and ShareAlike for distributed adaptations. Q10.b must exclude non-text media, fair-use material, and pages with third-party or license notices that cannot be preserved, and store each exact oldid permalink with the prepared manifest. For API use, follow [API etiquette](https://www.mediawiki.org/wiki/API%3AEtiquette): identify the client, issue serial requests, and use `maxlag` for noninteractive runs. This correction supersedes the chapter-based split wording in the paragraph above: the split unit is a complete article revision.

This is a bounded English-encyclopedia diagnostic, not a broad capability benchmark. The source terms reviewed do not expressly discuss language-model training; treating reuse under the page's CC BY-SA terms as sufficient for this local research use is an interpretation, not an explicit AI-training grant. No source text or trained model will be published under this Q10 package. Any later distribution of derived artifacts needs a separate license review. Q10.b must use a descriptive API User-Agent, serial requests and `maxlag`, freeze the exact article/revision inventory before fetching bodies, and stop if per-page licensing or attribution cannot be verified. The source API metadata endpoint was unavailable from the restricted checkout during the initial Q10.b preparation package; no revision IDs have been guessed and no replacement corpus has been downloaded.

### Q10.b candidate inventory preregistration (23 September 2026)

Before querying revision metadata, freeze the candidate titles and eligibility rules in [`q10b_wikipedia_candidate_inventory.json`](q10b_wikipedia_candidate_inventory.json). The list contains 24 titles across six topical strata. Use every eligible title; do not select pages based on their content or model scores. At least 20 pages must pass. Each selected revision must be wikitext, at most 1 MiB, and the combined source revision size must not exceed 4 MiB. If the bound or minimum is not met, stop and amend the candidate-set decision before requesting any article bodies.

The metadata-only query requests title/page identity, latest revision ID, timestamp, byte size, SHA-1, content model, and edit comment. It does not request `rvprop=content`. The English Wikipedia [Revisions API](https://www.mediawiki.org/wiki/API%3ARevisions) documents these metadata fields separately from revision content. Use one request for all candidates where supported, otherwise serial batches, with `maxlag=5` and a descriptive User-Agent under [API etiquette](https://www.mediawiki.org/wiki/API%3AEtiquette). After revision IDs are frozen, inspect each exact revision's footer, history and discussion for the license and attribution conditions described in the [Wikimedia Terms of Use](https://foundation.wikimedia.org/wiki/Terms_of_Use?useformat=mobile) and [developer guidance](https://foundation.wikimedia.org/wiki/Legal%3AWikimedia_Developer_App_Guidelines). Do not fetch article bodies unless at least 20 pages pass every metadata, size, license and attribution rule. Record excluded pages and reasons; no silent substitutions.

For early infrastructure checks, `configs/smoke.json` creates a fixed synthetic fixture automatically. Its scores are not downstream language-capability evidence.

## Existing synthetic-domain control

The already-prepared M1 TinyStories subset can serve as a narrow architecture stability and cache-resource control while a natural-language corpus is reviewed. The pinned dataset card identifies the stories as synthetic and declares `CDLA-Sharing-1.0`. The [agreement](https://cdla.dev/sharing-1-0/) permits use of the data and places same-agreement conditions on publishing received or enhanced data; Section 3.5 says it imposes no restrictions on results. The [CDLA FAQ](https://cdla.dev/faq-resources/faq/) distinguishes those results from data that contains more than a de minimis portion of the source. Keep the raw and prepared text local; publish only aggregate results and provenance. This establishes a disclosed synthetic domain, not broad or human-authored language capability.

The experiment subset remains bytes 0-20,971,519 from the pinned training file and the existing deterministic 2% document holdout; its source revision and transformation are recorded below. Before reusing the local files, verify their manifest hashes against the recorded run artifacts. Do not silently rebuild or substitute the split.

## Reproducing the bounded TinyStories subset

The M1 corpus run uses bytes 0–20,971,519 of `TinyStories-train.txt` at the pinned `roneneldan/TinyStories` revision `f54c09fd23315a6f9c86f9dc80f725de7d8f9c64`. The [dataset card](https://huggingface.co/datasets/roneneldan/TinyStories/blob/f54c09fd23315a6f9c86f9dc80f725de7d8f9c64/README.md) declares `cdla-sharing-1.0` and describes the dataset as synthetic short stories. The experiment deterministically holds out 2% of selected documents from this training prefix; it does not use the dataset's separate validation file. This bounded split verifies training and evaluation plumbing, not broad capability.

`scripts/prepare_tinystories_prefix.py` splits on `<|endoftext|>`, discards the last partial story if the byte range cuts through one, and collapses story whitespace to single spaces. It writes one document per line and a provenance sidecar containing the dataset revision, source file, license, byte range, upstream size, raw-prefix SHA-256, complete-story count, discarded-tail size, and text transformation. It refuses to overwrite the downloaded prefix or either existing prepared output. Pass the sidecar to `frontier prepare-data --source-metadata`; the resulting split manifest is copied into every run. Raw and prepared corpus files remain local under the root `data/` directory, which is git-ignored.
